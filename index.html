Look closer

Most software gives you the same answer twice by luck. We do it by design.

The field's answer

Take the same program to a second computer and you can get a second answer. Almost all software has this problem, and it's unsolved across the whole industry. Most tools settle for looking the same.

Ours

We mean answering the same. The same program gives back the same answer on the graphics card, on the software, and on the compiler that builds itself. Every number is a real run you can check.

Check it once, trust it everywhere

Prove a behavior on one machine and the proof stands on all of them. One audit covers every deployment.

Sanguis has a twin: BloodCode.

BloodCode: 29 instructions. Fixed numbers, fixed spellings, fixed meanings.

Frozen forever

Assigned slots never change. Deprecated ops keep their number. Changing a slot's spelling fails the build.

Any machine can join

A new executor (another GPU, an FPGA, a microcontroller) is admitted by passing one public per-operation test suite. Adding hardware never splits the language.

It's all just text

Artifacts are text. Open one in an editor and read exactly what your program became.

BloodCode docs

A running program is a file.

Write it out. Pick it back up somewhere else. It comes back bit-identical.

Unplug it

A core writes itself to a small package: its wiring, its weights, its clock. Insert it into a fresh process and it resumes where it was, the same program.

Replay it

Because the settle is deterministic, any behaviour re-runs bit-for-bit years later, on hardware that didn't exist when it was written.

Ask it why

Every result has a computed cause. Debugging stops being an anecdote and becomes a measurement.
