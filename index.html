The field's answer

Cross-machine determinism sits unsolved on every roadmap in the industry. Floating point rounds differently on every chip, so results drift the moment they move. Most tooling settles for identical builds. We mean identical behaviour.

Ours

Rounding is a contract, not an accident. The same program produces the same bytes on the card, the just-in-time executor, and the compiler that compiles itself. Every number is a real run you can check.

A frozen instruction set, asserted every time the compiler builds itself.

BloodCode: 29 slots. Fixed numbers, fixed spellings, fixed semantics.

Frozen forever

Assigned slots never change. Deprecated ops keep their number. Changing a slot's spelling fails the build. A contract, not a convention.

Any machine can join

A new executor (another GPU, an FPGA, a microcontroller) is admitted by passing one public per-operation test suite. Adding hardware never splits the language.

Readable down the instruction

Artifacts are text. Open one in an editor and read exactly what your program became.

BloodCode docs

A running program is a file.

Write it out. Pick it back up somewhere else. Bit-identical.

Unplug it

A core writes itself to a small package: its wiring, its weights, its clock. Insert it into a fresh process and it resumes where it was, the same program.

Replay it

Because the settle is deterministic, any behaviour re-runs bit-for-bit years later, on hardware that didn't exist when it was written.

Ask it why

Every result has a computed cause. Debugging stops being an anecdote and becomes a measurement.

Deterministic computing is the floor under anything you have to trust.
